## Purpose

Phase 6 turns the confirmed six-vehicle definitions into inspectable Roblox models without publishing them to the garage. It creates:

- six cockpit templates using the current Viper cockpit visual and slot hierarchy;
- 72 core module templates: six donors × front engine/rear engine/stabilisers/boost × Standard/Lightweight/Power;
- 48 upgradable modules containing 144 path definitions;
- confirmed raw stats, default module IDs, point-cost guides, target tiers, and cockpit price guides.

## Why ServerStorage staging

The garage automatically discovers any cockpit with a `CockpitId` beneath the live `ReplicatedStorage.NeoTokyoRacers.Assets.Vehicles.Categories` hierarchy. Placing Zenith there now would expose it before V2 rating, physics, legacy compatibility fields, purchases, and six-point persistence are ready.

Phase 6 therefore writes only to:

```text
ServerStorage
  NeoTokyoRacers
    VehiclePerformanceV2_Staging
```

This is intentional generated staging, not a backup. The root is marked `CatalogPublishReady = false`, can be safely regenerated by the canonical script, and is invisible to players and garage discovery.

## Visual donor policy

- Every staged cockpit clones the complete current Viper cockpit model, including slots, colour groups, VFX attachments, and root contract.
- Each staged core module clones the matching current Viper Standard/Lightweight/Power module donor.
- IDs, display names, source cockpit ownership, front/rear engine metadata, stats, paths, prices, and default-module links are rewritten per vehicle.
- No existing live cockpit or module is replaced.

## Studio script

Run in Studio Edit mode:

`scripts/roblox_vehicle_performance_v2_phase6_asset_materialisation_staging.lua`

The script performs no source text replacement and creates no backup objects. On a rerun, it clears only a staging root carrying its exact ownership marker; an unrelated existing folder causes a hard stop.
