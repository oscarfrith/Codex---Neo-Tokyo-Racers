# RaceEntry family (F5): notes for the integrator

State: **generated only.** Nothing was compiled, run or installed (no offline Luau here). ## 2. API questions and the reading used

1. **No kit component draws a content image** (track map, large vehicle picture). The views create one plain `ImageLabel` each (`Picture`, `VehiclePicture`): `BackgroundTransparency = 1`, `ScaleType = Fit`, no colour. This is the only non-kit GuiObject besides transparent holder Frames. If lint refuses it, a `Surface.Image` constructor is the fix. Image ids are normalised in the model exactly as `RacingUIComponents.Asset` does (digits become `rbxassetid://...`); that one string prefix is in `RaceEntryModel._image`.
2. **Where a view may write `Position` and `Size`.** API1 says screens hold no coordinates, A2 3.6 gives `header.Height()` "so a screen can stack a body under it". Reading used: a view creates transparent holder Frames under a slot, sizes them from slot positions (`TopLeft`, `BottomRight`, `RightColumn`, `RailButtons`), kit component sizes and tokens, and kit components fill the holders. `Position` is also written on the roots of `Text.Label`, `Chip` and `TierBadge` (the Phase 1 kit never writes a root's `Position`). No pixel literal is used; `HALF = 0.5` splits columns.
3. **Panel pad on Compact.** `Surface.Panel.Set({Pad = Space.TouchGap})` on Compact, `Space.Pad` on Regular. If `Pad` is meant to be fixed, remove the `Set` in the three `layout` functions.
4. **Marks on panels.** `Surface.Panel` has no `MarkKey`, and the Phase 1 `Surface` rewrites a root's `Name` on every relayout, so `PrizeSummary`, `MedalTargets` and `RaceFormat` are marked on the holder Frame around the panel (`Input.Mark(holder, key)`). `LapSelector` uses `Stepper`'s `MarkKey`; the tier and mode tabs use `MarkKey` items. **If `Stepper` or `Tabs` re-apply their own `Name` after marking, Classic onboarding page 18 breaks**: check in Play.
5. **`Stepper.Format`** is given `model.LapText` (`"3 LAPS"`). `Stepper.Set({Value, Min, Max})` is called on every render; the `SetupView` test asserts this does not call `OnChanged` (a kit that does would loop back into the model, harmlessly, but the test will say so).
6. **`Collections.List`** is used for the leaderboard with `Header = {"POS", "PLAYER", "VEHICLE", "TIME"}` and items `{Key, Columns = {4 strings}, Accent = isYou}`; no `Title`, no `OnActivated`. If `ListRow` needs `Title`, pass `Columns[2]`. Twenty rows at budget 12 would be 240 instances, over the page budget of 220: the view test will show the real number. The `Limit = 20` payload is not changed.
7. **`Data.FactList`** rows are `{Id, Icon, Label, Value, Kind}` with icons `medal`, `trophy`, `checkpoints`, `players`, `race_flag`, `laps`, `timer`. When its root has no offset height the views fall back to `rows x Px(FactRowHeight)` (Regular) or `rows x Px(StatRowHeight)` (Compact); there is no Compact fact-row token, which is a token request if the real height differs.
8. **`Rail`**: `SetHeading(text, count)`, `SetItems`, `Select`, `Set({Visible})` are used; `Tile` items carry `Status = "Locked"` and no `Selectable`, so locked tiles are inert. The rail has no "nothing selected" call, so with no eligible vehicle the kit's last selection (if its key still exists) stays lit; the button row still reads `SELECT A VEHICLE`.
9. **`Header`** is assumed to honour `Visible` through `Set`, to expose `header.Tabs.Select`, and to take `Count` beside the title ("RECORDS"). Each page has its own header; only the shown page's is visible.
10. **Status cluster.** Frames 03, r11 and r12 draw the vehicle, rank and cash strip top right. It is not built: A2 5.6 gives this family one static layer and `CashChip` must sit on a live one. Say if it is wanted (it needs `RaceEntryPresentationLive` in the ladder).
11. **Scrim.** The client puts `Surface.Scrim({Kind = "Menu"})` into `layer.ScrimRoot`. If `Layers.Create(..., {Scrim = true})` already draws one, remove that line.
12. **Gallery `Mount`.** The items use `Frame = "Menu"`, `Slot = nil`; `Mount` builds its own `Layers.Stage` inside the parent it is given and mounts the view on it. The fixtures list also carries `_fakeModel` and `_snapshots` as non-array fields for the tests.
13. **Test harness.** The view and fixture tests need the kit v2 sources and this family's six sources in one `after` listing, and `env.Scope()`. `RaceEntryModel_test` and `RaceEntryClient_test` need nothing else. `RaceEntryModel_test` prints one expected `[Pulse.RaceEntryModel] a Changed listener failed` warning.
14. **`start()` waits.** Classic waits without limit for `Remotes.Racing.RaceRequest`, `Remotes.Garage.GarageInvoke`, `Runtime.Racing.RaceEntryPresentationRequest` and `RaceEntryLegacyAction`. Pulse `start()` looks them up without yielding; if one is absent it returns `ready`, wires the screen from a background task when the object appears, and warns after 10 s naming what is missing. The only yield in `start()` is `WaitForChild("PlayerGui")`, as in the toast owner.
15. **`Data.Money`'s first call may yield** (A2 3.5). It is called while the model builds a snapshot, so the first open can pause there once. A snapshot overtaken during that pause keeps its old `Revision` and no view draws it.
16. **A view that throws** (for example a kit signature that differs from A2) does not leave the player on a blank scrim: the client warns once and calls `model.Exit()`, which fires `Close`. Under Pulse the race entry would then close on every open; the console line is `[Pulse.RaceEntryClient] render failed: ...`.

## 3. What the integrator must check in Play (Pulse, sandbox window)

1. Walk to a start zone: the page appears at once on time-trial Setup with EXIT enabled; `LOADING` turns into `CHOOSE VEHICLE` or the `OWN A X CLASS VEHICLE TO ENTER` text; the highest owned tier is selected.
2. **Payload parity.** Record `RaceEntryLegacyAction` arguments under Classic and under Pulse for the same choices: time trial (tier, lap count changed, a non-default vehicle) and race. Keys and values must be equal: `Mode, EventId, VehicleId, CockpitId, Tier, LapCount`. Then confirm the bridge does its part (vehicle spawns; time trial stages; the race queue banner shows). Do not cross a time-trial finish.
3. EXIT fires `Close` once; `FreeRoamHudPresentationMode` is `{Owner = "RaceEntry", Active = true}` on open and `false` on exit and on start, on a touch emulation too; the HUD comes back.
4. Rapid input: click tiers and tabs as fast as possible during the first second, then NEXT, BACK, CHOOSE: one footer row at all times, the personal best always matches the selected tier, no page from the previous open.
5. Prize preview: race Setup for each tier fixture equals Classic's three figures (live config 1 / 0.85 / 0.65, nearest 250, 0 to 50000).
6. Classic onboarding replay of pages 17 to 19 on a fresh sandbox profile: EventMode finds the two tabs, TimeTrialSetup finds the tier row, prize panel, medal targets and lap selector (callout positions on Regular and Compact), RaceSetup finds `RaceFormat`; none of them fires on Records or Vehicles.
7. Census: one `RaceEntryPresentation` and one `RaceEntryPresentationScrim`, both marked Pulse, `Enabled` never written, root hidden while closed; `instance_census` per page at most 220; `churn_probe` 0 on tier, lap and vehicle clicks.
8. Layout at R720, R1080, R1440, C844, C568 through the gallery (`RaceEntry.Setup`, `RaceEntry.Records`, `RaceEntry.Vehicles`): the vehicle button row on the rail heading line (slot `RailButtons`), tier colours on the tier buttons and badges, the long gate text inside the main button, the Compact tier row beside the tabs without touching them, the Records list inside its panel, the fact panel clear of the rail on Compact.
9. Gamepad: tabs by bumpers are **not** enabled (`Bumpers` is not passed, because two tab rows share the page); focus enters the footer row; the rail selects on focus.
10. Images: a track with a `MapImage` and vehicles with `MenuImage` draw in the plain ImageLabels; with none, the panels stay empty without error.
